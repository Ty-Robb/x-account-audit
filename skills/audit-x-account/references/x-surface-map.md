# X growth surface map

Use this map to decide which X surface, official source, evidence standard, and suite workflow apply to a request. It covers X features that can materially affect organic account growth; it is not a user manual for advertising, payments, direct messages, developer APIs, or unrelated consumer settings.

Last editorial review: 14 August 2026. The source monitor checks the published algorithm daily and the wider official-source registry weekly.

## 1. Evidence contract

Use these labels consistently:

- **Published code:** behaviour directly visible in the pinned `xai-org/x-algorithm` snapshot. It may still be controlled by runtime configuration or experiments.
- **Official product guidance:** a capability, specification, eligibility rule, or policy stated by X Help or X's recommender-system disclosures.
- **Observed:** public account or owner-supplied evidence captured for the audit.
- **Practice:** a creative or operating recommendation to test; never present it as an algorithm rule.
- **Unknown:** private runtime state, unavailable analytics, an unverified current specification, or a system that X has not published.

When sources disagree, prefer the newest official product documentation for product availability and the pinned source code for claims specifically about that published implementation. Flag the disagreement instead of blending the claims.

## 3. Publishing formats

| Surface | Primary official source | Growth use | Suite treatment |
| --- | --- | --- | --- |
| Original posts | [How to post](https://help.x.com/en/using-x/how-to-post) | Creates stand-alone discovery inventory | Core format in every stage; require a clear audience job and honest proof |
| Replies and mentions | [Mentions and replies](https://help.x.com/en/using-x/mentions-and-replies) | Builds conversation, context, and real relationships | Separate from original inventory; make every reply specific and useful |
| Reposts and quote posts | [Reposting](https://help.x.com/en/using-x/how-to-repost) | Curates or adds a distinct point of view | Treat quotes and plain reposts separately because published paths distinguish them |
| Threads | [Create a thread](https://help.x.com/en/using-x/create-a-thread) | Explains a sequence or layered argument | Judge the whole conversation; do not count every thread item as an independent Home opportunity |
| Hashtags | [How to use hashtags](https://help.x.com/en/using-x/how-to-use-hashtags) | Adds explicit context when the tag is genuinely used by the audience | Use sparingly and descriptively; do not prescribe a magic number |
| Links and cards | [Post links](https://help.x.com/en/using-x/how-to-post-a-link) | Sends people to evidence, products, or owned assets | Make the feed post useful on its own and inspect destination trust |
| Single and multi-image posts | [Posting images and GIFs](https://help.x.com/en/using-x/posting-gifs-and-pictures) | Shows proof, diagrams, comparisons, screenshots, or emotion | Verify current upload limits and use alt text; choose dimensions for the intended crop, not an alleged boost |
| Image descriptions | [Image descriptions](https://help.x.com/en/using-x/write-image-descriptions) | Makes visual information accessible | Include concise, meaningful alt text when an image conveys information |
| GIFs | [Posting images and GIFs](https://help.x.com/en/using-x/posting-gifs-and-pictures) | Adds a reaction, illustration, or motion cue | Use only when it adds meaning; do not substitute it for evidence |
| Video | [Videos on X](https://help.x.com/en/using-x/x-videos) | Demonstrates, teaches, narrates, or builds familiarity | Verify current upload limits; use accurate captions, a legible first frame, and an audience-relevant job |
| Live video | [Live video](https://help.x.com/en/using-x/x-live) | Creates real-time coverage and interaction | Recommend only with a clear event and moderation plan |
| Articles | [About Articles](https://help.x.com/en/using-x/articles) | Publishes durable, structured long-form work | Verify eligibility; pair with useful feed excerpts and a clear title |
| Polls | [X polls](https://help.x.com/en/using-x/x-polls) | Collects lightweight audience input | Use for a genuine decision or learning question, not empty interaction bait |
| Spaces | [About Spaces](https://help.x.com/en/using-x/spaces) | Hosts live audio, expertise, interviews, and community | Plan topic, speakers, moderation, recap, and follow-on assets |
| Community posts | [Communities](https://help.x.com/en/using-x/communities) | Serves a bounded interest group | Measure community value separately from broad Home inventory |

Exact format limits change. Recheck the linked official source whenever file size, duration, dimensions, aspect ratio, character count, eligibility, or subscription access determines the deliverable. Creative working sizes belong in stage playbooks and must be labelled **Practice**.

## 6. Measurement and creator surfaces

| Surface | Primary official source | Use | Suite treatment |
| --- | --- | --- | --- |
| Post activity | [Post activity dashboard](https://help.x.com/en/managing-your-account/using-the-post-activity-dashboard) | Supplies owner-only impressions and engagement detail | Prefer consistent windows and medians; label owner-supplied metrics |
| Creator dashboard | [Creator dashboard](https://help.x.com/en/using-x/creator-dashboard) | Centralises available creator tools and performance | Verify current availability and do not infer missing data |
| Public counts | Public post and profile views | Enables a lower-confidence external audit | Capture date and observation window; do not compare unlike windows |
| Subscriptions | [Subscriptions](https://help.x.com/en/using-x/subscriptions) and [creator setup](https://help.x.com/en/using-x/subscriptions-creator) | Converts audience trust into recurring support where eligible | Optimise audience value before monetisation; verify eligibility and terms |
| Creator revenue sharing | [Creator revenue sharing](https://help.x.com/en/using-x/creator-revenue-sharing) | Provides an optional platform revenue path | This suite is for audience growth; revenue eligibility is not a content-quality signal |
| Owned destinations | Destination analytics supplied by the owner | Measures qualified conversion beyond X | Track only necessary aggregate data and never store credentials |
| Under the Hood | [Published implementation](https://github.com/xai-org/x-algorithm/tree/main/under-the-hood) | May expose eligible owner-only account and post labels | Never retrieve another person's report or diagnose hidden labels from reach |

The core operating comparison window is 48 hours where practical because it creates comparable rows and aligns with a published Home age path. It is a measurement convention, not a claim that every X surface stops distributing after 48 hours.

## 7. Safety, visibility, and automation

| Area | Primary official source | Required treatment |
| --- | --- | --- |
| Recommendation eligibility | [Recommendation standards](https://help.x.com/en/rules-and-policies/recommendations) | Treat eligibility as a prerequisite; distinguish it from ranking quality |
| Reach limitation | [About reach-limited posts](https://help.x.com/en/rules-and-policies/x-reach-limited) | Use owner-visible notices or official evidence; never diagnose a hidden penalty from weak performance |
| Authenticity and platform manipulation | [Authenticity](https://help.x.com/en/rules-and-policies/authenticity) and [platform manipulation](https://help.x.com/en/rules-and-policies/platform-manipulation) | Reject coordinated engagement, deceptive identities, metric inflation, and follow churn |
| Duplicate content | [Duplicate and copypasta policy](https://help.x.com/en/rules-and-policies/copypasta-duplicate-content) | Require material variation, real context, and human review of generated work |
| Automation | [Automation rules](https://help.x.com/en/rules-and-policies/x-automation) | Do not prescribe automated posting or interactions without checking the current rules and API terms |
| Free or purchased followers | [Free followers policy](https://help.x.com/en/safety-and-security/free-x-followers-policy) | Never recommend follower buying, exchanges, or credential-sharing schemes |
| Spam, unsafe links, impersonation, abuse | [X Rules](https://help.x.com/en/rules-and-policies/x-rules) | Check content, quoted context, destination safety, and account integrity before optimisation |
| Accessibility | [Image descriptions](https://help.x.com/en/using-x/write-image-descriptions) and current format guidance | Add meaningful alt text, captions, readable contrast, and non-colour-only meaning |

Do not turn policy evasion into a growth tactic. If a strategy depends on hiding automation, manufacturing engagement, copying content, misleading users, or bypassing a platform control, reject it.

## 8. Suite coverage by workflow

| Workflow | Owns | Reads from other areas |
| --- | --- | --- |
| `$setup-x-growth` | Persistent account, ledger, experiment, series, and decision records | The shared state schema only |
| `$audit-x-account` | Public evidence, surface diagnosis, source interpretation, stage selection, comparison, teardown | Algorithm signals, rubric, report template, compact content fallback, this map |
| `$launch-x-account` | Positioning, profile, first 15 posts, sustainable launch loop | Current profile and publishing specifications, cold-start evidence, safety |
| `$learn-x-account` | Comparable measurement, controlled content tests, retain/revise/stop decisions | Post formats, analytics, discovery evidence, trust |
| `$systemize-x-account` | Pattern cards, series grammar, portfolio, production, conversion | Media formats, profile conversion, diversity and repetition constraints |
| `$compound-x-account` | Adjacencies, durable assets, collaborations, owned conversion, resilience | Articles, video, Spaces, Communities, creator tools, policy |

The audit skill is the diagnostic router. Stage skills own execution. This boundary keeps invocation predictable while allowing the audit's compact fallback to work when installed alone.

## 9. Known limits

- X can change product names, access, specifications, policies, experiments, and runtime configuration without changing the public repository.
- The published code is not a complete representation of every X surface or production path.
- No public audit can see viewer-level candidate sets, predicted probabilities, private graph features, experiment assignment, hidden labels, private analytics, or the causal reason for an individual impression count.
- Help pages sometimes block automated retrieval. A retrieval failure is a monitoring warning, not evidence that the page changed.
- The suite covers organic creator and account growth. Paid ads, campaign buying, developer API implementation, payments operations, private-message strategy, and general platform support are out of scope unless a future dedicated workflow is added.
- Exact upload specifications must be rechecked at the time of production. A remembered dimension or entitlement must not be presented as current merely because it appears in an older playbook.
