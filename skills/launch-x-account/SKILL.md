# Launch an X Account

Build a credible, publishable starting system for an account with no dependable audience or performance evidence.

## Accept the minimum useful input

Start with any combination of:

- intended audience and the problem the account will help with;
- creator expertise, experience, examples, work, or other credible proof;
- account goal, offer, link destination, time budget, and preferred formats;
- a draft handle, profile, website, or existing account being fully repositioned.

If important context is missing, ask only for the audience, recurring value, and credible proof in one short question. Do not require an X API key, analytics, followers, or an existing post archive.

## Load the stage method

Read [references/day-zero-playbook.md](references/day-zero-playbook.md) before building the launch plan. Use its entry and exit criteria, profile specifications, first-15 matrix, measurement ledger, and failure checks.

## Use persistent state when present

If `.x-growth/` exists in the current project, read `workspace.json` and `account.md` before planning. Use the stored objective, audience, proof, constraints, and stage when they remain current; surface conflicts instead of silently choosing one version.

For an ongoing workspace, write confirmed positioning and stage changes to `account.md`, append material choices to `decisions.md`, and add ledger rows only after posts are actually published. Re-read target files before editing and preserve user changes. The skill must also work without persistent state.

## Follow the workflow

### 1. Confirm stage fit

Use this stage when no reliable post-performance pattern exists. Treat a dormant or fully repositioned account as Day zero when its old audience and content are not relevant to the new promise.

State that follower count is not the stage definition. The published small-author scorer uses a follower threshold, but that isolated rule is not a universal account-maturity model.

### 2. Build the positioning spine

Define:

1. one primary audience;
2. one recurring problem or ambition;
3. one credible promise;
4. the creator's proof and point of view;
5. three connected content pillars;
6. a clear boundary describing what the account will not cover.

Reject vague claims, invented credentials, and an audience definition broad enough to include everyone.

### 3. Prepare the profile

Write the display name, bio, banner message or direction, link call to action, and pinned-post outline. Treat these as human conversion surfaces, not proven ranking inputs.

Use current platform specifications from the playbook when dimensions matter. Label working templates as creative recommendations rather than algorithm requirements.

### 4. Create the first 15 posts

Create five posts per pillar unless a different split is justified. Vary the content job, evidence, angle, and format. Make each post understandable to a relevant stranger and useful without earlier context.

For every post, provide:

- pillar and content job;
- draft or precise opening and core value;
- creator-specific proof needed before publishing;
- natural reader action, if earned;
- media brief and accessibility note only when media adds value.

Never fabricate personal experience, customer results, data, or quotations. Mark proof placeholders clearly.

### 5. Establish the operating loop

Recommend a sustainable publishing and conversation routine based on the creator's time budget. Measure every post on a consistent 48-hour window where possible. Use medians after enough posts exist and revise after the first 15.

Encourage specific, useful participation in relevant conversations. Do not prescribe follow churn, engagement pods, bulk replies, repetitive templates, or arbitrary high-volume targets.

### 6. Deliver the launch pack

Return, in this order:

1. launch diagnosis and assumptions;
2. positioning spine;
3. completed profile copy and asset brief;
4. three-pillar content architecture;
5. first 15 posts or detailed briefs;
6. manageable 30-day routine;
7. measurement ledger;
8. Day-zero exit criteria and first review date.

## Keep evidence honest

Label claims as `Observed`, `Code-backed`, `Practice`, `Experiment`, or `Unknown`. Explain that published cold-start treatment is a possible small-author sampling opportunity that acts only after candidate retrieval; it is not a promise that new accounts receive reach.

Do not diagnose hidden restrictions, forecast impressions, call a preferred posting time an algorithm rule, or optimise solely for follower count.
